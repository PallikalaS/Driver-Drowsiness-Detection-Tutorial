There are three broad ways to make the final decision. Rule-based systems use thresholds chosen by people. Feature-based machine learning keeps the hand-designed measurements but lets an algorithm learn how to combine them. Deep learning, covered in Section 7, learns everything directly from images. This page covers the first two, which are often called "traditional" approaches even though many production systems still rely on them.

Traditional computer vision methods: rules and thresholds

The simplest drowsiness detector is a set of if-then rules built on the measurements from earlier sections:

  • If EAR stays below 0.20 for 15 consecutive frames → "wake up" alert (Section 3).
  • If PERCLOS over the last minute exceeds a set percentage → "take a break" warning (Section 3).
  • If three or more yawns occur in 10 minutes → "take a break" warning (Section 4).
  • If a nod is detected → "wake up" alert (Section 5).

Real systems add two refinements. Grace periods require a condition to persist before acting, so a brief glitch doesn't trigger an alarm. Priorities decide what happens when several rules fire at once. Zambrano et al. combined fixed thresholds with grace periods and gave fatigue alerts priority over distraction alerts, choosing fixed values to keep the system fast and reproducible [3].

How well does a pure threshold rule work? Herath et al. tested a classic EAR rule on real driver videos from the UTA Real-Life Drowsiness Dataset: it reached a precision of 0.812 and a recall of 0.82 [6]. In other words, about one in five of its drowsy calls was wrong, and it missed about one in five drowsy cases. That is a useful baseline, and the gap is what machine learning tries to close.

Feature extraction and classification

Machine learning changes the question from "which threshold should I pick?" to "given many labeled examples, what combination of measurements best separates alert from drowsy?" The pipeline looks like this:

Step 1: summarize time windows into features

A classifier doesn't look at single frames. It looks at a window, such as the last 60 seconds, and describes it with a feature vector: a short list of numbers that capture how the driver behaved during that window. Typical features include:

Researchers summarize this family of choices as eye-based, mouth-based, and head-based behavioral features, often fed to classic classifiers [2].

Step 2: label the windows

To learn, the algorithm needs examples whose answer is known. Common labels come from asking drivers to rate their own sleepiness every few minutes on a standard scale such as the 9-point Karolinska Sleepiness Scale, or from expert observers rating recorded video. Labels can be binary (alert or drowsy) or graded (alert, moderately drowsy, very drowsy). Section 8 explains why good labels are hard to collect.

Step 3: train a classifier

Several classic algorithms work well on small feature vectors:

  • Support Vector Machine (SVM): finds the boundary that separates the two classes with the widest possible margin. With a kernel, the boundary can curve. SVMs work well with modest amounts of data.
  • k-Nearest Neighbors (k-NN): stores every training window. To classify a new one, it finds the k most similar windows and takes a vote. Simple and easy to explain, but every feature must be scaled to a similar range, or the feature with the largest numbers dominates the distance.
  • Random forest: trains many decision trees, each on a random slice of the data and features, and lets them vote. It handles mixed features well and reports which features mattered most.

In practice, a few lines of Python with the scikit-learn library train and evaluate all three. Note the GroupKFold split, which keeps each driver's windows together so the model is always tested on people it has never seen (Section 8 explains why this matters):

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC
from sklearn.neighbors import KNeighborsClassifier
from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import GroupKFold, cross_val_score

# X: one row per window [perclos, blink_rate, blink_dur, max_closure, yawns, nods]
# y: 0 = alert, 1 = drowsy;  groups: driver ID for each window
models = {
    "SVM": make_pipeline(StandardScaler(), SVC(kernel="rbf")),
    "k-NN": make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5)),
    "Random forest": RandomForestClassifier(n_estimators=200),
}
for name, model in models.items():
    scores = cross_val_score(model, X, y, groups=groups, cv=GroupKFold(n_splits=5), scoring="f1")
    print(f"{name}: F1 = {scores.mean():.2f}")

StandardScaler rescales every feature to a similar range, which SVM and k-NN need; random forests don't, because each tree split looks at one feature at a time.

Advantages and limitations

AdvantagesLimitations
Explainable: every decision traces back to a measurement anyone can understand, such as "PERCLOS was 22%."Only as good as the features: if a sign of drowsiness isn't in the feature list, the model can't learn it.
Fast: runs easily in real time on a phone or small CPU.Inherits landmark errors: head pose, glasses, and lighting distort EAR and MAR, and fixed thresholds often need recalibration per driver [6].
Data-efficient: works with hundreds of labeled windows instead of the many thousands of images deep learning needs.Individual differences: one driver's normal is another's drowsy, as the small-eyes problem showed [3].

When to choose this approach: when the system must run on modest hardware, when decisions need to be explainable (for example, to justify an alert to a fleet operator), or when only a small labeled dataset is available. When accuracy matters most and data and computing power are plentiful, deep learning is usually stronger, as the next section shows.

Key takeaways

  • Rule-based systems combine thresholds, grace periods, and priorities; a plain EAR rule reached about 0.81 precision and 0.82 recall on real driver video.
  • Feature-based machine learning summarizes time windows into features such as PERCLOS, blink duration, yawns, and nods, then learns how to combine them.
  • SVM, k-NN, and random forests all work well on small feature vectors; scale features for SVM and k-NN.
  • Traditional methods are fast and explainable but can only learn from the features people design.
